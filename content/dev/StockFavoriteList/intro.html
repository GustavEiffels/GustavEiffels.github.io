Side Project Spring Boot React WebSocket Telegram Bot 2026-02-26 ~ 2026-04-24

혼자 쓸 주식 즐겨찾기·평단가·알람 도구가 필요해서 시작한 1인 풀스택 프로젝트. 약 2개월 동안 기능을 추가할 때마다 작업 보고서를 남겼고, 여기서는 그 기록을 모아 무엇을 만들었는지 소개한다.

Chapter 1

즐겨찾기 & 평단가 관리

드래그 앤 드롭 순서 변경 (2/26)

  • 드롭 시 프론트엔드 상태를 먼저 갱신(낙관적 UI)하고 500ms debounce 후 서버에 저장 — 매번 호출하지 않고 사용자가 정렬을 끝낸 시점에만 API를 호출
  • 등락에 따라 종목 카드 테두리 색을 동적으로 표시

평단가(Cost Price) 관리 — 2단계 확장

  • 1차(2/26): 종목당 최대 5개 평단가 등록, 현재가 대비 수익률 색상 표시
  • 2차(4/24): quantity·avgExchangeRate·brokerageFeePercent 필드를 추가해 수량·환율·수수료까지 반영한 실질 손익으로 확장. 이를 위해 Yahoo USD/KRW 환율을 1분마다 폴링해 Caffeine 캐시에 적재하는 실시간 환율 도메인을 신설

주식 메모(Comment)

  • 종목당 최대 5개, 평단가 기능과 동일한 4-Layer 아키텍처 패턴 재사용
  • 메모 작성/수정 시 현재가·등락률을 본문에 자동 삽입 — 신규 작성은 맨 앞 prepend, append 편집은 경계에 삽입, 내용 수정 시 기존 태그 제거 후 새 태그로 교체(4/14)
Chapter 2

실시간 알람 시스템

최초 구현 (3/3)

기술적 지표(EMA, SMA, RSI) 또는 가격 조건을 기준으로 알림을 발송. 중첩 조건 최대 5개, 재알림 주기 설정, 차트 모달과 연동.

조건 강화 (3/24)

  • 전일 종가 대비 % 알람 조건 추가
  • 알람이 작동할 마켓 세션(Pre-Market / 정규장 / After-Hours / 전체) 선택
  • 텔레그램 ID 프로필 등록 UI/API

구조 전환 — 브라우저 의존성 제거 (3/27)

기존엔 브라우저(프론트엔드)에서만 알람 조건을 평가했기 때문에 브라우저를 닫으면 알람이 멈췄다. 이를 서버사이드 평가로 옮기고, 동시에 사용자별 KIS API 키를 등록받아 실시간 WebSocket 시세를 쓰고, 미등록 사용자는 Yahoo Finance 폴링으로 자동 fallback하는 구조로 전환했다.

"조용히 실패"하던 버그 4가지 (3/27)

  • AlarmPriceScheduler가 STOMP 구독을 "이미 처리 중"으로 간주해 Yahoo 폴링을 스킵
  • STOMP disconnect 시 subscriberCounts가 정리되지 않아 유령 구독이 영구히 남음
  • 스케줄러 스레드에서 LazyInitializationException이 발생했지만 조용히 삼켜짐
  • @Transactional self-invocation — 같은 클래스 내부 호출이라 트랜잭션이 적용되지 않음
공통점 네 버그 모두 "겉으로는 정상 동작하는 것처럼 보이지만 조용히 실패"하는 유형이었다. 추측으로 고치지 않고 매번 재현 테스트를 먼저 작성해 원인을 확정한 뒤 수정했다.
Chapter 3

차트 & 기술적 지표

  • ChartLine(3/7) — 차트에 수평선/추세선을 그려서 서버에 저장·수정·삭제하는 기능을 풀스택으로 구현
  • 캔들 비교 & range 버그(3/8) — 여러 차트 인스턴스 간 캔들 등락률 비교 기능 추가, 초기 30개 캔들만 보여줘야 하는데 첫 진입 시에만 적용이 안 되던 race condition 수정
  • 조건 필터 & StochasticRSI(4/3) — 알람 조건 기준 캔들 마커 필터, %K/%D 보조 지표 추가, dayHigh/dayLow/openPrice를 활용해 실시간 캔들 OHLC 정확도 개선
Chapter 4

텔레그램 봇 — 웹과 동등한 기능 이식

  • 알림 + 인라인 관리(3/26) — 알람 조건 충족 시 Telegram 발송, 인라인 키보드로 알람 조회/추가/수정/삭제(웹과 동일 옵션)
  • 지표 조회 + 가격 라벨(4/14) — 티커별 RSI/StochRSI/SMA·EMA(9개 기간)/다중 세션 가격을 한 번에 조회, 웹의 CostPrice 기능을 봇 플로우로 이식
설계 원칙 웹과 텔레그램 봇이 같은 Facade 레이어를 재사용하도록 설계해, 기능을 추가할 때마다 두 클라이언트의 로직이 갈라지지 않고 동일한 데이터 소스를 공유하게 했다.
Chapter 5

인프라 & 배포

  • Backend + Frontend를 Docker/Nginx 없이 Spring Boot 단일 jar로 통합 서빙, 빌드/배포/종료 스크립트 제공(3/26)
  • 로컬 PostgreSQL + Backend + Frontend를 한 번에 띄우고 종료하는 개발 환경 스크립트
  • Per-user KIS WebSocket(등록 사용자) / Yahoo 폴링(미등록 사용자) fallback 구조로 외부 API 의존도를 분산

한 줄 정리

  • 약 2개월, 15개 기능 단위 작업, 매번 "왜 이렇게 했는가"를 기록으로 남김
  • 평단가 기능은 단순 입력에서 환율·수수료까지 반영한 실질 손익 계산으로 점진 확장
  • 알람은 프론트엔드 평가 → 서버사이드 평가로 구조 자체를 바꿔 브라우저 의존성을 제거
  • "조용히 실패"하는 버그(Lazy 로딩, self-invocation 트랜잭션, 유령 구독)는 재현 테스트로 원인을 확정한 뒤 고쳤다
  • 웹과 텔레그램 봇이 같은 Facade를 공유해, 기능이 늘어도 로직이 두 갈래로 갈라지지 않게 했다
