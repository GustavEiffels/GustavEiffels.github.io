Longest Palindrome

홀수 카운트 판정 기준을 result의 홀짝과 섞어서 틀렸던 버그를 고친 과정

언어: Java 분류: 그리디 / 해시맵 핵심 기법: 문자 빈도 카운팅 + 홀수 보정

leetcode.com/problems/longest-palindrome

CH 1

풀이 회고

1

문제 개요

문자열의 문자들을 자유롭게 재배열해서 만들 수 있는 가장 긴 팰린드롬의 길이를 구하는 문제다.
원본 문자열의 순서는 상관없고, 문자별 개수만 중요하다.

2

시행착오 - 홀수 판정 기준을 잘못 잡음

Map/HashMap으로 문자 빈도부터 세는 구조로 시작했는데, import를 안 넣어서 첫 실행에
컴파일 에러가 났다. import 추가하고 나서 실제 로직에서 더 큰 문제가 나왔다.

버그 - 홀수 판정 기준을 잘못 잡음 result % 2 == 0으로 홀수 카운트 여부를 판단했다. count가 홀수인지와 result의 현재 홀짝은 서로 무관한 값인데 섞어서 썼다. abccccdd 기준 7이 나와야 하는데 6이 나왔다 - a(1), b(1)처럼 홀수 count를 만나는 시점에 result가 계속 짝수(0)라서 odd 처리가 한 번도 안 걸리는 구조였다.
3

수정 및 확인

수정

count % 2 == 1을 직접 판정하는 boolean odd 플래그로 바꾸고,
루프가 다 끝난 뒤에 딱 한 번만 +1 하도록 고쳤다.

확인 1 - 홀수 카운트가 여러 개여도 +1은 항상 한 번

홀수 count인 문자가 3개(a,b,c 각 3개)든 몇 개든, 팰린드롬 가운데 자리는 한 칸뿐이라
+1은 항상 최대 1이다.

확인 2 - 원본 순서는 무관

재배열이 허용되는 문제라, 원본에서 문자 순서가 어떻게 섞여 있든(444123444 같은 배치)
count만 맞으면 상관없다.

4

최종 코드

LongestPalindrome.java 
public int longestPalindrome(String s) {
    Map<Character, Integer> map = new HashMap<>();
    for(char c : s.toCharArray()) {
        map.put(c, map.getOrDefault(c, 0) + 1);
    }
    int result = 0;
    boolean odd = false;
    for(int count : map.values()) {
        result += (count / 2) * 2;
        if(count % 2 == 1){
            odd = true;
        }
    }
    if(odd){
        result += 1;
    }
    return result;
}
5

Takeaway

  • 홀수 판정은 count 자체로 해야지, result의 현재 홀짝과 섞으면 안 된다.
  • 홀수 카운트가 몇 개든 팰린드롬 가운데 자리는 하나뿐이라, +1은 항상 최대 한 번이다.
