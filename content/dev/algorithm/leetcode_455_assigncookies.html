Assign Cookies

정렬 + 투 포인터로 매칭 개수를 최대화하는 그리디 문제 풀이 과정

언어: Java 분류: 그리디 핵심 기법: 정렬 + 투 포인터

leetcode.com/problems/assign-cookies

CH 1

풀이 회고

1

문제 개요

g[i]는 인덱스가 아니라 그 자리 값 자체가 아이의 탐욕 기준이다. s[j]도 마찬가지로 값이 쿠키 크기다.

목표는 조건(s[j] >= g[i])을 만족하는 매칭 개수의 최댓값을 구하는 것이고,
쿠키 개수 자체도 상한이 된다 - g=[3,4,5], s=[100,100]이면 둘 다 조건은 만족해도
쿠키가 2개뿐이라 답은 2다.

2

시행착오 - Collections.sort를 int[]에 그대로 씀

버그 - Collections.sort를 int[]에 그대로 씀 Collections.sort(s, Collections.reverseOrder())를 int[]에 썼다가 컴파일 에러가 났다. Collections.sort는 List 대상 메서드라 기본형 배열엔 적용이 안 된다. Arrays.sort(g), Arrays.sort(s)로 교체했다.
3

풀이 - 정렬 + 투 포인터

첫 풀이

정렬 후 투 포인터로 풀었다. while(true) + 맨 아래 break 구조로 짰다.

AssignCookies.java — 첫 풀이 
while(true){
    int cookieSize = s[cookieIndex];
    int kidSize = g[kidIndex];
    if(cookieSize >= kidSize){
        result++; cookieIndex++; kidIndex++;
    } else {
        cookieIndex++;
    }
    if(cookieIndex >= s.length || kidIndex >= g.length) {
        break;
    }
}

정리 버전

루프 조건 자체에 두 인덱스 조건을 넣는 방식으로 정리해서 길이 0 예외 처리와
break문을 없앴다.

AssignCookies.java — 정리 버전 
public int findContentChildren(int[] g, int[] s) {
    Arrays.sort(g);
    Arrays.sort(s);

    int result = 0;
    int cookieIndex = 0;
    int kidIndex = 0;

    while (cookieIndex < s.length && kidIndex < g.length) {
        if (s[cookieIndex] >= g[kidIndex]) {
            result++;
            kidIndex++;
        }
        cookieIndex++;
    }
    return result;
}

시간복잡도와 제출 결과

정렬 O(n log n)이 이 문제의 사실상 하한이라 더 줄일 방법은 없다. 값 범위가 작다는 보장이 있으면 counting sort로 더 낮출 수 있지만 일반적인 경우엔 해당 없다.

Takeaway

  • g[i]/s[j]는 인덱스가 아니라 값 자체가 기준이고, 쿠키 개수 자체도 상한이 된다.
  • Collections.sort는 List 전용, 기본형 배열엔 Arrays.sort를 써야 한다.
  • 정렬 O(n log n)이 이미 하한이라, 값 범위 제약 없이는 더 줄일 수 없다.
