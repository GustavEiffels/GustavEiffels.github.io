문제

Claude에게 추천받은 코딩테스트 사이트 LeetCode에서 푼 첫 문제다.

문제는 영어로 되어 있지만 읽을 수 있는 수준이라 그대로 읽었다.
배열 요소 중에서 두 개를 더해 target이 되는 조합을 찾고, 그 두 요소의 index를 배열로 반환하면 된다.
정답은 항상 하나만 존재한다고 명시되어 있고, 같은 index를 두 번 쓰는 건 허용되지 않는다.

2

1차 시도 — brute force

이 정도 문제는 그냥 이중 for문으로 풀면 된다고 생각해서 그렇게 풀었다.

TwoSum.java — brute force 
public int[] twoSum(int[] nums, int target) {
    int length = nums.length;
    for (int i = 0; i < length; i++) {
        for (int j = i + 1; j < length; j++) {
            if (nums[i] + nums[j] == target) {
                return new int[]{i, j};
            }
        }
    }
    return new int[]{1, 2};
}

제출하니 정답은 맞았는데, 성능 평가는 상위 70%였다.
배열 길이가 n일 때 비교 횟수가 n^2에 가까워서, 입력이 커지면 느려지는 구조다.

O(n^2) 정답 / 성능 하위권

개선 — HashMap 보수 탐색

더 나은 방법이 없는지 찾아보다가 다음 코드를 발견했다.

TwoSum.java — HashMap 
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> valueToIndex = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        Integer j = valueToIndex.get(complement);
        if (j != null) {
            return new int[]{j, i};
        }
        valueToIndex.put(nums[i], i);
    }
    return new int[]{1, 2};
}

처음엔 왜 이렇게 짰는지 바로 이해가 가지 않았다.

왜 이렇게 짰는지

어차피 배열을 한 번은 순회해야 하니, 그 순회 중에 "target에서 현재 값을 뺀 수"를 key로 해서
그 값이 이미 나온 적 있는지를 확인하는 방식이다.

예를 들어 target이 10이고 현재 뽑은 수가 4라면, map에서 6을 찾는 셈이다.
6이 이미 map에 있으면 그 값의 index와 현재 index를 반환하면 된다.
즉 "남은 반쪽이 이미 지나갔는지"만 확인하면 되는 구조라서, 안쪽 루프로 매번 나머지 원소를 다시 훑을 필요가 없어진다.

결과 이 방식으로 다시 제출하니 성능이 상위 20% 수준으로 개선됐다.
O(n) 정답 / 성능 상위 20%

Takeaway

  • 이중 루프는 매번 "나머지 원소 훑기"를 반복하는 게 낭비 포인트다.
  • "두 수를 더해 target을 만든다"를 "필요한 짝이 이미 나왔는가"로 뒤집으면 한 번의 순회로 풀린다.
  • HashMap 조회는 O(1)이라 안쪽 루프를 대체할 수 있다.
