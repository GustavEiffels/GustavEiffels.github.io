문제

0부터 입력된 숫자 n까지, 각 정수를 2진수로 나타냈을 때 1의 개수를 배열로 반환하는 문제다.

DP 문제이므로 i번째 값을 구할 때 이전에 이미 구해둔 dp 값을 어떻게든 재사용하는 방향으로 접근해야 한다.

참고 바로 앞에 푼 Climbing Stairs는 순수 점화식 문제라 풀다가 AI Assistant 답을 먼저 봐서 이번 정리에서는 생략. Counting Bits는 직접 점화식을 찾아낸 케이스라 기록할 가치가 있다.

감이 안 오면 나열해본다

작은 수부터 이진수로 변환해서 1의 개수를 나열하는 것보다, 조금 더 큰 수 구간에서
나열해보는 쪽이 패턴이 잘 보일 것 같아서 32부터 나열했다.

32는 2^5라서 1의 개수가 1이다.
33은 32에 1을 더한 것, 34는 32에 2를 더한 것 - 그 말은 1이 두 개라는 뜻이다.
같은 식으로 39는 32에 7을 더한 것으로 볼 수 있다.

3

분해해서 점화식 찾기

39 = 32 + 7로 쪼개고, 7도 다시 4 + 3으로 쪼갰다.

39 = 32 + 7 = 32 + (4 + 3)

bits(32) = 1, bits(4) = 1, bits(3) = 2 (3 = 011이라 1이 두 개).
이 셋을 더하면 1 + 1 + 2 = 4가 되고, 실제로 39의 1의 개수와 일치한다.

여기서 32, 4, 3은 서로 비트가 겹치지 않는 구간(몫과 나머지 관계)이라서, 각 조각의
1의 개수를 그냥 더하면 전체 1의 개수가 된다는 걸 확인했다.

핵심 관찰 몫과 나머지로 나누면 비트가 겹치지 않으니, 이미 구해둔 더 작은 수의 bits 값을 그대로 재사용할 수 있다. 이게 DP 점화식의 근거다.
4

코드

위 관찰을 가장 단순한 형태로 옮기면, i를 2로 나눈 몫과 나머지로 쪼개는 식이 된다.
나머지는 0 또는 1뿐이라 dp[0]=0, dp[1]=1만 미리 채워두면 그대로 재사용할 수 있다.

CountingBits.java 
public int[] countBits(int n) {
    if (n <= 0) return new int[]{0};
    if (n == 1) return new int[]{0, 1};
    int[] dp = new int[n + 1];
    dp[0] = 0;
    dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i / 2] + dp[i % 2];
    }
    return dp;
}

dp[i / 2]는 "몫" 쪽 비트 수, dp[i % 2]는 "나머지" 쪽 비트 수(0 또는 1)다.
39 = 32 + 7로 손으로 쪼갠 것과 본질은 같고, 코드에서는 매번 2로 나누는 가장 작은 단위로 쪼개서 누적한다.

O(n) Bottom-up DP

Takeaway

  • 점화식이 바로 안 보이면 작은 수부터 나열해서 패턴을 눈으로 확인하는 게 먼저다.
  • 몫과 나머지처럼 비트가 겹치지 않게 쪼개면, 이미 구한 dp 값을 그대로 더해 재사용할 수 있다.
  • 오랜만에 점화식을 직접 찾아서 깔끔하게 푼 DP 문제였다.
