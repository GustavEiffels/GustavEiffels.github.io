N-th Tribonacci Number

점화식을 손으로 먼저 전개해보고, 기저값을 잘못 적었던 실수를 코드 실행으로 잡아낸 과정

언어: Java 분류: 동적 계획법 (DP) 핵심 기법: dp[i] = dp[i-1] + dp[i-2] + dp[i-3]

문제 개요

T0=0, T1=1, T2=1이 주어지고 n>=3부터는 Tn = Tn-1 + Tn-2 + Tn-3으로
정의되는 점화식에서 n번째 값을 구하는 문제다. 피보나치의 항이 3개로 늘어난 버전이다.

2

손으로 먼저 전개 - n=4 검증

코드를 짜기 전에 n=4를 손으로 직접 펼쳐서 점화식이 맞는지부터 확인했다.

손 풀이 - n4 전개 
n4 = n3 + n2 + n1
   = (n2+n1+n0) + n2 + n1      // n3을 다시 n2+n1+n0으로 치환
   = 2*n2 + 2*n1 + n0
   = 2*1 + 2*1 + 0
   = 4

n3 자체를 값으로 안 쓰고 한 단계 더 풀어써서 n4가 결국 n0, n1, n2 세 항목의 조합으로만 표현된다는 걸 확인했다.
이어서 n7 = n6+n5+n4 자리에도 같은 치환이 반복된다는 걸 적어두고, 매 항이 "바로 이전 3개"에만 의존하니
배열에 이전 값을 누적해서 채워나가면 된다는 결론으로 넘어갔다.

3

DP 테이블 설계

손 풀이에서 확인한 대로, dp 배열의 각 칸은 "직전 3칸의 합"이라는 하나의 규칙만 따르면 된다.
기저값 3개만 먼저 채우고 나머지는 반복문으로 밀고 나가는 전형적인 상향식(bottom-up) DP다.

인덱스 값 비고
dp[0] 0 기저값
dp[1] 1 기저값
dp[2] 1 기저값
dp[i] (i>=3) dp[i-1]+dp[i-2]+dp[i-3] 점화식 그대로
4

시행착오 - 기저값을 잘못 적었던 것

손 풀이 노트에는 처음에 "T2=2"로 잘못 적어서 n4 = 5라는 계산을 얻었었다.
실제 코드를 T2=1이라는 정의 그대로 짜서 돌려보니 dp[4] = 4가 나왔고, 그 차이를 보고 손 풀이 쪽 기저값이 틀렸다는 걸 알았다.

기저값은 T0=0, T1=1, T2=1이 맞다 손으로 전개할 때 T2 자리에 2를 넣었던 게 원인이었다. 배열로 직접 실행해서 나온 값(dp[4]=4)과 손 풀이 결과(5)를 대조해보고 나서야 기저값 설정이 틀렸다는 걸 바로 확인할 수 있었다.
5

최종 코드

Tribonacci.java 
public int tribonacci(int n) {
    int[] dp = new int[n + 1];
    for(int i = 0; i <= n; i++){
        if(i < 3) {
            if(i == 0) dp[i] = 0;
            else dp[i] = 1;
        }
        else{
            dp[i] = dp[i-1] + dp[i-2] + dp[i-3];
        }
    }
    return dp[n];
}

Takeaway

  • 손으로 n4를 직접 치환해서 펼쳐보니 "직전 3항에만 의존"하는 구조가 눈에 보였고, 이게 그대로 dp 배열 설계로 이어졌다.
  • 손 풀이에서 기저값을 T2=2로 잘못 적었던 걸 코드 실행 결과(dp[4]=4)로 바로 확인했다 - 실제 정의는 T0=0, T1=1, T2=1이다.
  • 손으로 먼저 전개하는 건 점화식 검증에 유용하지만, 기저값처럼 사소한 오타는 코드로 직접 돌려봐야 잡힌다.
