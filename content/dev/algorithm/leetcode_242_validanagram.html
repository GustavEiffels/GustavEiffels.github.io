Valid Anagram

정렬로 먼저 정답을 만들고, 문자 빈도 카운팅으로 더 나은 시간복잡도를 검토한 과정

언어: Java 분류: 정렬 / 해시맵 핵심 기법: 정렬 후 비교 → 빈도 카운팅으로 개선 검토

leetcode.com/problems/valid-anagram

CH 1

풀이 회고

1

문제 개요

문자열 t가 문자열 s의 애너그램(같은 문자들을 다른 순서로 배열한 문자열)인지 판별하는 문제다.
두 문자열의 길이가 다르면 애초에 애너그램이 될 수 없고, 길이가 같다면 "구성 문자와 각 문자의 개수가 완전히 일치하는가"만 확인하면 된다.

2

1차 시도 — 정렬 후 비교

"구성 문자와 개수가 같다"를 가장 직관적으로 확인하는 방법은 두 문자열을 각각 정렬해서
같은 위치의 문자가 전부 일치하는지 보는 것이다. 순서가 달라도 정렬하면 같은 배열이 되기 때문이다.

ValidAnagram.java 
public boolean isAnagram(String s, String t) {
    if(s.length() != t.length()){
        return false;
    }
    char[] first = s.toCharArray();
    char[] second = t.toCharArray();
    Arrays.sort(first);
    Arrays.sort(second);

    for(int i = 0; i<s.length(); i++){
        if(first[i] != second[i]){
            return false;
        }
    }
    return true;
}

길이 검사로 먼저 걸러내고, 남은 두 문자열을 정렬해서 인덱스별로 비교하는 방식으로 정답을 맞았다.
다만 Arrays.sort()가 내부적으로 O(n log n)이라, 이 문제가 요구하는 이상으로 비용을 쓰고 있다는 게 마음에 걸렸다.

O(n log n) 정답 / 정렬 비용 존재
3

개선 검토 — 빈도 카운팅

"순서를 맞출 필요 없이 개수만 같으면 된다"는 조건이라면, 굳이 정렬까지 갈 필요가 없다는 생각이 들었다.
알파벳 소문자만 대상이라는 제약을 활용하면, 길이 26짜리 배열 하나로 각 문자의 등장 횟수를 세는 게 가능하다.

아이디어 s를 순회하며 문자별 카운트를 +1, t를 순회하며 같은 배열에 -1한다. 두 문자열이 애너그램이면 모든 카운트가 정확히 0으로 돌아온다 - 배열 하나로 양쪽을 동시에 상쇄시키는 방식이다.

이렇게 하면 정렬 없이 두 문자열을 한 번씩만 훑는 것으로 끝나서 O(n)이 된다.
다만 이번 풀이에서는 정렬 방식이 이미 통과했고 문제 제약(길이 5000 이하)에서 체감 성능 차이가 크지 않아서, 실제 코드는 정렬 버전으로 남겨두고 개선 방향만 정리해뒀다.

O(n) (검토만)
4

Takeaway

  • "순서 무관, 구성만 같으면 된다"는 조건은 정렬(O(n log n))보다 카운팅(O(n))이 더 잘 맞는 신호다.
  • 길이 검사를 가장 먼저 넣어두면 이후 로직에서 인덱스 범위를 신경 쓸 필요가 없어진다.
  • +1/-1로 같은 배열을 양쪽에서 상쇄시키는 패턴은 "두 컬렉션의 구성이 같은가"를 확인할 때 자주 재사용할 수 있다.
