Happy Number

자릿수 제곱합을 반복하다가 사이클에 빠지는지를 HashMap으로 감지한 과정

언어: Java 분류: 해시맵 핵심 기법: 이미 나온 값을 저장해 사이클 감지

leetcode.com/problems/happy-number

CH 1

풀이 회고

1

문제 개요

숫자 n을 "각 자릿수의 제곱의 합"으로 계속 바꿔나가다 결과가 1이 되면 happy number다.
문제는 이 과정이 항상 1로 끝난다는 보장이 없다는 점이다 - 어떤 시작값은 같은 몇 개의 수를 무한히 순환하기만 한다. 그래서 "언제 멈춰야 하는지"를 먼저 정해야 했다.

2

접근 — 사이클 감지가 핵심

1이 나오면 바로 true를 반환하면 되지만, 문제는 1이 안 나오는 경우다.
무한루프를 막으려면 "이 값은 이미 한 번 나왔었다"를 알아채야 한다고 생각해서, 지금까지 나온 결과값을 HashMap에 저장해두고 매번 확인하는 방식으로 접근했다.

왜 사이클이면 무조건 false인가 같은 수가 두 번 나왔다는 건, 그 시점부터 결과가 똑같은 흐름을 계속 반복한다는 뜻이다. 그 반복 안에 1이 없었다면 앞으로도 영원히 안 나온다 - 그래서 사이클 발견 = 즉시 false로 확정할 수 있다.
3

최종 코드

HappyNumber.java 
public boolean isHappy(int n) {
    int number = n;
    Map<Integer,Boolean> resultMap = new HashMap<>();

    while (true) {
        int result = operation(number);

        if(result == 1){
            return true;
        }
        else{
            if(resultMap.containsKey(result)){
                return false;
            }
            resultMap.put(result, true);
            number = result;
        }
    }
}

public int operation(int n){
    int number = n;
    int result = 0;
    while((number/10) != 0){
        int digit = (int) Math.pow(10, String.valueOf(number).length()-1);
        result += Math.pow(number/digit, 2);
        number = number%digit;
    }
    result += Math.pow(number%10, 2);
    return result;
}

제출 결과는 2ms(상위 15.54%), 메모리 42.70MB(상위 11.96%)였다.
정답은 맞지만 속도·메모리 둘 다 중위권이라, 어느 쪽이 병목인지 다음 섹션에서 다시 봤다.

4

아쉬운 점 — 자릿수 분리 방식

operation() 안에서 자릿수를 뽑아내는 방식이 지금 보면 과하게 복잡하다.
String.valueOf(number).length()로 자릿수를 구하고 Math.pow(10, ...)로 최상위 자릿값을 만든 다음, 그걸로 나누고 나머지를 구하는 식으로 한 자리씩 앞에서부터 처리했다.

더 단순하게 갈 수 있었던 부분 자릿수 제곱합은 순서와 무관하므로, 굳이 앞자리부터 뽑을 필요 없이 number % 10과 number /= 10만 반복해도 같은 결과가 나온다. 지금 방식은 매 반복마다 문자열 변환 + Math.pow 호출이 끼어 있어서, 단순 정수 연산만 쓰는 방식보다 느릴 수밖에 없는 구조다.
5

Takeaway

  • 결과가 무한히 반복될 수 있는 문제에서는 "이미 나온 상태"를 저장하는 것 자체가 종료 조건이 된다.
  • 자릿수 분리는 순서가 필요 없다면 문자열 변환 없이 % 10 / / 10 반복만으로 충분하다.
  • 정답이 나왔다고 끝이 아니라, 제출 성능(시간/메모리) 수치를 보고 병목 후보를 다시 짚어보는 습관이 필요하다.
