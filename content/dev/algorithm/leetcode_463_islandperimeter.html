Island Perimeter

DFS + marker 배열로 통과는 했지만 Runtime Beats 5.92%가 나와서, 왜 느린지 원인을 뜯어보고 O(n·m) 단일 순회로 다시 푼 회고

언어: Java 분류: DFS / 배열 핵심 기법: 재귀 DFS → 단일 순회 + 인접 카운팅

leetcode.com/problems/island-perimeter

CH 1

첫 풀이 — DFS로 섬 하나를 순회하며 변 개수 세기

1

문제 개요

0/1로 이루어진 그리드가 주어지고, 섬(연결된 1의 덩어리)은 정확히 하나만 존재하며 호수는 없다고 가정한다. 이 섬 전체의 둘레(perimeter)를 구하는 문제다.

육지 칸 하나는 상하좌우 4변을 가지는데, 이웃한 칸도 육지면 그 변은 바다와 접하지 않으므로 둘레에서 빠져야 한다. 즉 "땅과 땅이 맞닿은 경계는 둘레가 아니다"가 핵심 규칙이다.

2

풀이 — 시작점을 찾아 DFS로 섬 전체를 순회

그리드를 훑어 처음 나오는 육지 칸을 시작점으로 잡고, 그 칸부터 DFS로 인접한 육지 칸을 전부 방문한다. 각 칸에서 기본값 4를 더한 뒤, 그리드 경계가 아닌 각 방향에 대해 directionDfs로 이웃을 확인한다 — 이웃이 바다면 0, 육지면 -1(맞닿은 변 제외) 하고 아직 방문 안 한 육지면 그 칸에서 재귀를 이어간다. marker 배열로 이미 방문한 칸은 중복 재귀하지 않도록 막는다.

N463_IslandPerimeter.java - 첫 풀이 
public int islandPerimeter(int[][] grid) {
    int row = grid.length;
    int col = grid[0].length;
    int[][] marker = new int[row][col];
    int startX = 0, startY = 0;

    // 첫 육지 칸을 시작점으로 탐색
    for (int i = 0; i < row; i++) {
        for (int j = 0; j < col; j++) {
            if (grid[i][j] == 1) {
                startX = i; startY = j;
            }
        }
    }
    return dfs(grid, marker, startX, startY, row, col);
}

public int dfs(int[][] grid, int[][] marker, int x, int y, int xSize, int ySize) {
    int result = 4;
    marker[x][y] = 1;

    if (y != 0)        result += directionDfs(grid, marker, x, y - 1, xSize, ySize);
    if (y != ySize - 1) result += directionDfs(grid, marker, x, y + 1, xSize, ySize);
    if (x != 0)        result += directionDfs(grid, marker, x - 1, y, xSize, ySize);
    if (x != xSize - 1) result += directionDfs(grid, marker, x + 1, y, xSize, ySize);
    return result;
}

public int directionDfs(int[][] grid, int[][] marker, int x, int y, int xSize, int ySize) {
    if (grid[x][y] != 1) return 0;
    int result = -1;
    if (marker[x][y] != 1) {
        result += dfs(grid, marker, x, y, xSize, ySize);
    }
    return result;
}

최적화 풀이 — 인접 카운팅 방식

"섬이 하나뿐"이라는 조건을 이용하면 굳이 연결 관계를 따라갈 필요가 없다. 그리드를 한 번만 훑으면서 육지 칸마다 +4를 더하고, 왼쪽 또는 위쪽이 이미 육지라면 그 경계가 두 칸 모두에서 중복 계산되므로 -2씩 빼는 방식이다. 각 칸을 한 번씩만 보므로 재귀도 marker 배열도 필요 없다.

N463_IslandPerimeter.java - islandPerimeterFast 
// DFS/재귀/marker 배열 없이 단일 순회로 계산.
// 육지 칸마다 +4, 왼쪽/위쪽이 육지면 그 경계가 중복 계산되므로 -2씩 차감.
public int islandPerimeterFast(int[][] grid) {
    int row = grid.length;
    int col = grid[0].length;
    int result = 0;

    for (int i = 0; i < row; i++) {
        for (int j = 0; j < col; j++) {
            if (grid[i][j] != 1) continue;
            result += 4;
            if (i > 0 && grid[i - 1][j] == 1) result -= 2;
            if (j > 0 && grid[i][j - 1] == 1) result -= 2;
        }
    }
    return result;
}
왜 왼쪽 · 위쪽만 확인해도 되는가 순회 순서상 오른쪽·아래쪽 이웃은 아직 방문 전이라 나중 칸을 볼 때 그 칸 기준으로 다시 왼쪽/위쪽 검사에 걸린다. 즉 모든 인접 쌍이 "나중에 순회되는 칸의 왼쪽 또는 위쪽 검사"에서 정확히 한 번씩 걸러지므로 네 방향을 다 볼 필요가 없다.

Takeaway

  • Accepted가 떴다고 성능까지 좋은 건 아니다 — Beats 5.92%는 로직이 아니라 구현 오버헤드(재귀, 배열 재할당, 남은 println)를 의심할 신호다.
  • DFS로 연결 요소를 순회하는 접근은 일반적이지만, "섬이 하나뿐"이라는 문제 제약을 쓰면 연결을 따라갈 필요 자체가 없어진다.
  • 인접 칸 검사를 왼쪽·위쪽 두 방향으로만 좁혀도 모든 경계 쌍이 정확히 한 번씩 걸러진다 — 순회 순서를 이용하면 검사량을 절반으로 줄일 수 있다.
  • 제출 전에 디버그용 System.out.println 같은 흔적을 지우는 습관이 필요하다.
