Teemo Attacking

인터벌 병합(객체화)으로 접근하려다, 단순 계산으로 충분하다는 걸 깨닫고 정리한 회고

언어: Java 분류: Array / Simulation 핵심 기법: 인접한 두 공격 시각의 차이를 duration과 비교

leetcode.com/problems/teemo-attacking

1

문제와 첫 시도 — 인터벌 병합처럼 접근

공격 시각 배열 timeSeries(오름차순)와 한 번의 공격이 지속시키는 duration이 주어진다. 각 공격은 그 순간부터 duration초 동안 중독 상태를 유지시키는데, 다음 공격이 그 안에 들어오면 중독 시간이 갱신될 뿐 중복으로 더해지지 않는다. 총 중독 상태였던 시간(초)을 구하는 문제다.

처음에는 구간(인터벌) 병합 문제처럼 접근하려고 했다. int end = 0을 두고, [1, 2] 예시(duration=3)를 손으로 그려보면서 "1은 2에서 끝난다(end=2)", "2는 3에서 끝난다"처럼 각 공격이 끝나는 지점을 객체처럼 들고 다니다가, 다음 공격 시각이 이전 end 안에 들어오는지(end ≥ i)를 비교하는 방식을 떠올렸다.

이 방식이 하려던 것 각 공격을 (시작, 끝) 구간으로 보고, 다음 구간의 시작이 이전 구간의 끝보다 앞이면 겹치는 것으로 처리 — 전형적인 "구간 병합" 패턴으로 풀려던 시도였다.
2

단순화 — 사실 그냥 계산 문제였다

구간 객체를 만들고 end를 갱신하는 로직을 짜다가, 결국 필요한 건 "각 공격과 바로 다음 공격 사이의 간격이 duration보다 작은지"만 판단하면 된다는 걸 깨달았다. 즉 ni - ni-1 < duration이면 두 공격의 중독 구간이 겹치므로 그 차이만큼만 더하고, 겹치지 않으면(간격이 duration 이상이면) duration 전부를 더하면 된다.

[1,2,3,4,5], duration을 손으로 대입해보며(간격 1이 duration보다 작은 케이스) 값을 하나씩 쌓아보니 result가 간격들의 합으로 정확히 맞아떨어지는 걸 확인했다. 객체를 만들어 구간을 들고 다닐 필요 없이, 배열을 한 번 순회하며 인접 차이만 비교하면 끝나는 문제였다.

핵심 아이디어 구간을 명시적으로 만들지 않아도, "간격 vs duration" 비교 하나로 겹침 여부와 겹치지 않을 때 더할 값이 동시에 결정된다. 마지막 공격의 duration만 루프 밖에서 한 번 더 더해주면 된다.
3

최종 코드

TeemoAttacking.java 
public int findPoisonedDuration(int[] timeSeries, int duration) {
    int result = 0;
    for (int i = 1; i < timeSeries.length; i++) {
        int num = timeSeries[i] - timeSeries[i - 1];
        if (num < duration) result += num;
        else result += duration;
    }
    return result + duration;
}

인접한 두 공격 시각의 차이가 duration보다 작으면 그 차이만, 아니면 duration 전체를 더한다. 루프는 마지막 공격을 포함하지 않으므로 끝나고 duration을 한 번 더 더해 마지막 공격분을 보정한다.

5

Takeaway

  • 처음엔 구간을 객체(start/end)로 다루는 인터벌 병합 방식으로 접근하려 했다.
  • 손으로 [1,2] 예시를 그려보다가, 결국 필요한 건 "간격 vs duration 비교" 하나뿐이라는 걸 깨달았다.
  • 간격이 duration보다 작으면 간격만큼, 아니면 duration 전부를 더하는 한 번의 순회로 충분하다.
  • 마지막 공격은 다음 값이 없으므로 루프 밖에서 duration을 별도로 더해 보정한다.
  • 시간복잡도 O(n), 공간복잡도 O(1) — 별도 자료구조 없이 배열 한 번 순회로 최적해에 도달했다.
