문제 개요

이진 트리의 root 노드가 주어졌을 때, 중위 순회(Inorder Traversal) — 즉 left → mid(node) → right 순서로 노드를 방문한 값을 리스트로 반환하는 문제다.
LeetCode가 이미 TreeNode root 형태로 완성된 트리를 넘겨준다.

2

착각했던 부분

문제에서 TreeNode root를 이미 인자로 주는데, 배열([1,2,3,4] 형태)을 직접 파싱해서 BFS로 트리를 새로 만들어야 하는 줄 착각했다.
그래서 inorderTraversalMakeNode / BFS 메서드를 먼저 만들었는데, 실제 제출에는 필요 없는 로직이었다.

착각의 원인 입력이 배열로 표시되는 LeetCode UI 표기([1,2,3,4])를 보고, "이 배열을 트리로 변환하는 것부터 내가 구현해야 한다"고 오해했다. 실제로는 그 변환은 LeetCode 내부에서 이미 끝나 있고, 함수는 완성된 TreeNode root만 받는다.

손코딩 정리 — 종이에 먼저 그려본 순회 로직

3

(착각한 채로) 배열 → 트리 생성 로직부터 손코딩

레벨 순서(BFS)로 큐에 넣어가며 부모-자식을 연결하는 방식을 먼저 종이에 정리했다.
Level 0 → queue에 root의 L, R 삽입. Level 1 → queue에 LL, LR, RL, RR 삽입 — 레벨이 내려갈수록 큐에 다음 레벨 후보 노드를 계속 offer하는 BFS 구조다.

실제 필요했던 것 — 중위 순회(DFS)만

left → mid → right 순서로 재귀 호출하면 끝나는 문제였다. root가 이미 주어지므로 3번 로직은 통째로 불필요했다.

손코딩 - DFS 의사코드 
public void DFS(TreeNode node) {
    if (node.left != null) {
        DFS(node.left);
    }
    sout(node.value());

    if (node.right != null) {
        DFS(node.right);
    }
}
핵심 깨달음 "배열을 트리로 바꾸는 일"과 "이미 있는 트리를 순회하는 일"은 완전히 다른 문제다. 문제가 어떤 형태의 입력을 함수 시그니처로 주는지부터 먼저 확인했어야 착각을 피할 수 있었다.
CH 3

제출 코드와 결과

5

최종 코드

N94_BinaryTreeInorderTraversal.java 
public List<Integer> inorderTraversal(TreeNode root) {
    List<Integer> result = new LinkedList<>();
    DFS(root, result);
    return result;
}

public void DFS(TreeNode node, List<Integer> result) {
    if (node == null) return;
    DFS(node.left, result);
    result.add(node.val);
    DFS(node.right, result);
}

null 체크로 재귀 종료 조건만 두면 되므로, 손코딩 버전보다 훨씬 단순해졌다 — left/right가 null이면 재귀가 그냥 멈추고 반환된다.

Takeaway

  • 문제가 배열을 UI로 보여줘도, 함수 시그니처가 이미 TreeNode를 받으면 트리 생성은 내가 할 일이 아니다.
  • 착각한 채로 배열 → 트리 변환(BFS) 로직을 먼저 손코딩했고, 이후 불필요함을 확인했다.
  • 실제 필요했던 건 left → mid → right 순서의 재귀 DFS 한 함수뿐이었다.
  • 재귀 종료 조건은 "node == null이면 return" 하나로 충분하다.
