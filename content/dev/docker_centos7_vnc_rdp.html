Docker CentOS 7 GUI 원격 접속

CLI 전용 CentOS 7 컨테이너에 XFCE + TigerVNC 또는 xrdp를 추가해 Windows Host에서 GUI 데스크탑으로 원격 접속하는 가이드. CentOS 7 EOL 대응 vault 미러 설정부터 VNC · RDP 비교까지 전 과정을 다룬다.

VNC 방식 TigerVNC + XFCE · 포트 5901 · RealVNC Viewer
RDP 방식 xrdp + XFCE · 포트 3390 · mstsc.exe (Windows 내장)
1

개요 & 환경

Docker의 centos:7 이미지는 순수 CLI 환경이다. 여기에 GUI 데스크탑 환경과 원격 접속 서버를 추가해 Windows에서 그래픽으로 접속할 수 있다. 두 가지 방법이 있으며 각각 다른 클라이언트를 사용한다.

항목VNC 방식RDP 방식
Base Imagecentos:7
GUI 환경XFCE4 (경량 데스크탑)
원격 서버TigerVNC Serverxrdp
포트59013390 (Host) → 3389 (Container)
클라이언트RealVNC Viewer (별도 설치)mstsc.exe (Windows 내장)
인증VNC 전용 패스워드OS 계정 (root + passwd)
CentOS 7 EOL 2024년 6월 공식 지원 종료. 보안 업데이트가 없으므로 테스트·학습 전용으로만 사용할 것. yum 미러도 폐쇄되어 반드시 vault.centos.org 아카이브 서버로 교체해야 한다 (Step 2).
2

VNC Step 1 — 컨테이너 실행

1Host PowerShell

VNC 포트(5901)를 열어두고 백그라운드로 컨테이너를 실행한다.

PowerShell — 컨테이너 실행 
# VNC 포트 5901 오픈
docker run -itd `
  --name centos7-test `
  -p 5901:5901 `
  centos:7

# 컨테이너 내부 접속
docker exec -it centos7-test /bin/bash
확인 포인트 이 시점에서 컨테이너는 순수 CLI 상태다. 이후 단계에서 GUI를 추가한다.
3

VNC Step 2 — Vault 미러 설정 (EOL 대응)

2컨테이너 내부

CentOS 7 EOL로 mirrorlist.centos.org가 폐쇄됐다. yum 실행 전 반드시 vault.centos.org 아카이브 서버로 교체해야 한다.

컨테이너 내부 — vault 미러 교체 
# mirrorlist 비활성화 + vault 서버로 baseurl 교체
sed -i 's/mirrorlist/#mirrorlist/g' /etc/yum.repos.d/CentOS-Base.repo
sed -i 's|#baseurl=http://mirror.centos.org|baseurl=http://vault.centos.org|g' \
  /etc/yum.repos.d/CentOS-Base.repo

# 캐시 초기화
yum clean all
이 설정 없이 yum 실행 시 발생하는 에러 Could not resolve host: mirrorlist.centos.org; Unknown error Cannot find a valid baseurl for repo: base/7/x86_64
4

VNC Step 3 — XFCE + TigerVNC 설치

3컨테이너 내부
EPEL 저장소 추가
EPEL 추가 
yum -y install epel-release
왜 EPEL? XFCE 패키지는 기본 CentOS 저장소에 없다. EPEL(Extra Packages for Enterprise Linux)을 먼저 추가해야 한다.
XFCE + TigerVNC 패키지 설치
패키지 설치 
yum -y install \
  tigervnc-server \
  xfce4-session \
  xfwm4 \
  xfdesktop \
  xfce4-panel \
  xfce4-terminal \
  dbus-x11 \
  xorg-x11-fonts-Type1
5

VNC Step 4 — 패스워드 & xstartup 설정

4컨테이너 내부
디렉터리 생성 & 패스워드 설정
VNC 패스워드 설정 
mkdir -p ~/.vnc

# 패스워드 입력 프롬프트 (예: test1234)
vncpasswd
XFCE 자동 실행 스크립트 작성
~/.vnc/xstartup 
cat > ~/.vnc/xstartup << 'EOF'
#!/bin/bash
unset SESSION_MANAGER
unset DBUS_SESSION_BUS_ADDRESS
exec startxfce4
EOF

chmod +x ~/.vnc/xstartup
xstartup 역할 VNC 서버가 시작될 때 XFCE 데스크탑을 자동으로 실행하도록 지정하는 스크립트다. 이 파일이 없거나 잘못 설정되면 VNC 접속 후 데스크탑이 뜨지 않는다.
6

VNC Step 5 — VNC 서버 시작

5컨테이너 내부
VNC 서버 실행 
vncserver :1 -geometry 1280x800 -depth 24

성공 시 아래와 같이 출력된다.

출력 예시 
New 'localhost:1 (root)' desktop is localhost:1
Starting applications specified in /root/.vnc/xstartup
Log file is /root/.vnc/localhost:1.log
옵션의미
:1디스플레이 번호 = 포트 5901 (5900 + 1)
-geometry 1280x800해상도 설정
-depth 24색상 깊이 (24bit)

RDP 방식 — Windows 원격 데스크톱 (mstsc)

xrdp를 설치하면 Windows에 기본 내장된 원격 데스크톱 연결(mstsc.exe)로 바로 접속할 수 있다. VNC Viewer 같은 별도 클라이언트 설치가 필요 없다.

항목내용
프로토콜RDP (Remote Desktop Protocol)
서버 패키지xrdp (EPEL)
포트Host 3390 → Container 3389
클라이언트Windows 원격 데스크톱 연결 (내장, 설치 불필요)
GUI 환경XFCE4 (동일)
Docker + systemd 제약 Docker 컨테이너는 기본적으로 systemd가 없다. xrdp를 systemctl 대신 바이너리를 직접 실행한다.
9

RDP Step 1 — 컨테이너 실행 (포트 3390)

1Host PowerShell
3389:3389 매핑 불가 Windows RDP 서비스가 이미 Host 3389를 점유하고 있어 mstsc가 컨테이너 대신 Windows 자체에 연결된다. Host 포트는 반드시 3390(또는 다른 포트)으로 변경한다.
PowerShell — 컨테이너 실행 
docker run -itd `
  --name centos7-rdp `
  -p 5901:5901 `
  -p 3390:3389 `
  centos:7

docker exec -it centos7-rdp /bin/bash
Vault 미러 설정 필수 yum 실행 전 반드시 VNC Step 2 (vault.centos.org 미러 교체)를 먼저 수행한다.
10

RDP Step 2 — xrdp + XFCE 설치

2컨테이너 내부
패키지 설치 
# EPEL 추가 (이미 설치됐으면 생략)
yum -y install epel-release

# xrdp + XFCE 설치
yum -y install \
  xrdp \
  xfce4-session \
  xfwm4 \
  xfdesktop \
  xfce4-panel \
  xfce4-terminal \
  dbus-x11 \
  xorg-x11-fonts-Type1
11

RDP Step 3 — 세션 설정 & root 패스워드

3컨테이너 내부
(1) .Xsession 설정
~/.Xsession 
echo "exec /usr/bin/xfce4-session" > ~/.Xsession
chmod +x ~/.Xsession
(2) startwm-bash.sh 수정 — 핵심
세션 즉시 종료 문제의 원인 xrdp는 /etc/xrdp/startwm.sh 가 아닌 /usr/libexec/xrdp/startwm-bash.sh 를 실제로 실행한다. 이 파일을 수정하지 않으면 접속 즉시 세션이 종료된다 — 가장 흔한 실패 원인.
/usr/libexec/xrdp/startwm-bash.sh 
cat > /usr/libexec/xrdp/startwm-bash.sh << 'EOF'
#!/bin/bash
exec /usr/bin/xfce4-session
EOF
chmod +x /usr/libexec/xrdp/startwm-bash.sh
(3) root 패스워드 설정
root 패스워드 
passwd root
# 새 패스워드 입력 (예: test1234)
패스워드 필수 RDP는 VNC와 달리 OS 계정으로 로그인한다. passwd 설정 없으면 접속 불가.
12

RDP Step 4 — xrdp 서버 시작

4컨테이너 내부

Docker에는 systemd가 없으므로 바이너리를 직접 실행한다.

xrdp 실행 
# 재시작 시 스테일 PID 파일 제거 (필수)
rm -f /var/run/xrdp.pid /var/run/xrdp-sesman.pid

# xrdp 시작
/usr/sbin/xrdp-sesman
/usr/sbin/xrdp

# 포트 리스닝 확인
ss -tlnp | grep 3389
# [::]:3389 LISTEN 상태이면 정상
정상 확인 [::]:3389가 LISTEN 상태로 출력되면 접속 준비 완료.
13

RDP Step 5 — mstsc.exe 접속

5Host Windows
(1) Host LAN IP 확인
PowerShell — LAN IP 확인 
ipconfig | findstr "IPv4"
# 예: 192.168.0.84
localhost 사용 불가 mstsc는 루프백(localhost / 127.0.0.1) RDP 연결을 차단한다. 반드시 실제 LAN IP를 사용해야 한다.
(2) 원격 데스크톱 연결 접속 정보
mstsc 접속 정보 
컴퓨터:       192.168.0.84:3390
사용자 이름:  root
암호:         (Step 3에서 설정한 패스워드)

정상 접속

XFCE 데스크탑 화면 표시

Windows 원격 데스크톱 내장 클라이언트 사용

접속 실패 시

localhost 사용 → LAN IP로 변경

세션 즉시 종료 → startwm-bash.sh 수정 확인

xrdp 미실행 → PID 삭제 후 재실행

패스워드 오류 → passwd root 재설정

유용한 명령어

VNC 서버 관리 (컨테이너 내부)
VNC 관리 명령 
# VNC 서버 종료
vncserver -kill :1

# VNC 서버 재시작
vncserver :1 -geometry 1280x800 -depth 24

# VNC 로그 확인
cat ~/.vnc/localhost:1.log
Docker 컨테이너 관리 (Host PowerShell)
Docker 관리 명령 
# 컨테이너 정지
docker stop centos7-test

# 컨테이너 재시작 후 VNC 재기동
docker start centos7-test
docker exec -it centos7-test vncserver :1 -geometry 1280x800 -depth 24

# 컨테이너 내부 접속
docker exec -it centos7-test /bin/bash

# 컨테이너 삭제
docker rm -f centos7-test

주의사항

항목내용조치
CentOS 7 EOL 2024년 6월 보안 업데이트 종료 테스트 전용으로만 사용
포트 충돌 5901 또는 3390이 이미 사용 중 Host 포트를 다른 번호로 변경
VNC 세션 유지 컨테이너 재시작 시 세션 끊김 vncserver :1 다시 실행 필요
EPEL 필수 XFCE 패키지가 기본 저장소에 없음 epel-release 먼저 설치
startwm-bash.sh RDP 세션 즉시 종료의 주요 원인 /usr/libexec/xrdp/startwm-bash.sh 수정 확인
VNC 보안 VNC는 기본적으로 암호화가 없다. 외부 네트워크에 노출된 환경에서는 SSH 터널링을 통해 접속해야 한다. ssh -L 5901:localhost:5901 user@server

VNC vs RDP 비교

항목VNC (TigerVNC)RDP (xrdp)
클라이언트 RealVNC Viewer 설치 필요 Windows 기본 내장 (mstsc)
Host 포트 5901 3390 (3389는 Windows RDP와 충돌)
인증 방식 VNC 전용 패스워드 (vncpasswd) OS 계정 (root + passwd)
핵심 설정 파일 ~/.vnc/xstartup /usr/libexec/xrdp/startwm-bash.sh
흔한 실패 원인 xstartup 미설정 startwm-bash.sh 미수정 (세션 즉시 종료)
서버 시작 vncserver :1 xrdp-sesman + xrdp 직접 실행
추천 상황 VNC 환경이 이미 있을 때 Windows Host에서 별도 설치 없이 접속

Quick Summary — VNC 방식

  • docker run -itd -p 5901:5901 --name centos7-test centos:7
  • sed 로 vault.centos.org 미러 교체 후 yum clean all
  • yum -y install epel-release tigervnc-server xfce4-session xfwm4 xfdesktop xfce4-panel xfce4-terminal dbus-x11
  • vncpasswd && ~/.vnc/xstartup 에 exec startxfce4 설정
  • vncserver :1 -geometry 1280x800 -depth 24
  • RealVNC Viewer → localhost::5901 접속

Quick Summary — RDP 방식

  • docker run -itd -p 5901:5901 -p 3390:3389 --name centos7-rdp centos:7
  • sed 로 vault.centos.org 미러 교체 후 yum clean all
  • yum -y install epel-release xrdp xfce4-session xfwm4 xfdesktop xfce4-panel xfce4-terminal dbus-x11
  • echo "exec /usr/bin/xfce4-session" > ~/.Xsession
  • /usr/libexec/xrdp/startwm-bash.sh 를 exec /usr/bin/xfce4-session 으로 교체 (핵심)
  • passwd root
  • rm -f /var/run/xrdp*.pid && xrdp-sesman && xrdp 실행
  • ipconfig 로 LAN IP 확인 후 mstsc → 192.168.x.x:3390 → root 로그인
